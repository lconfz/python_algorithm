```python
# 任务 1：原地去重
def remove_duplicates(nums):
    i = j = 1
    while j < len(nums):
        if nums[j] != nums[i-1]:
            nums[i] = nums[j]
            i += 1
        j += 1
    return i


# 任务 2：旋转数组（三次反转）
def reverse(nums, start, end):
    while start < end:
        nums[start], nums[end] = nums[end], nums[start]
        start += 1
        end -= 1


def rotate(nums, k):
    k %= len(nums)
    reverse(nums, 0, len(nums) - 1)
    reverse(nums, 0, k-1)
    reverse(nums, k, len(nums) - 1)


# 任务 3：移动零
def move_zeros(nums):
    i, j = 0, 1
    while j < len(nums):
        if nums[i] == 0 and nums[j] != 0:
            nums[i], nums[j] = nums[j], nums[i]
            i += 1
        j += 1
    return nums
```

## AI Feedback

**Acknowledge（做得好的地方）**：
- 任务 1 非常优雅：用 `nums[i-1]` 与 `nums[j]` 比较，天然避开了"先写后比"的顺序陷阱，是比 `nums[i] != nums[j]` 更稳的写法。
- 任务 2 三次反转完全正确，且 `k %= len(nums)` 处理了大 k；`k=0` 时两次整体反转自动抵消，边界也稳。
- 任务 3 的交换版思路正确，交换用元组语法（O(1) 空间），符合"原地"要求。

**Socratic follow-up（发现的边界 bug）**：
- 补充用例 `move_zeros([1, 0, 2])` 失败（输出 `[1, 0, 2]`，期望 `[1, 2, 0]`）。正式测试 `[0,1,0,3,12]`、`[0,0,1]` 恰好都以 0 开头，掩盖了此问题。
- 根因推演：当 `nums[i] != 0` 时 `i` 永不前进，卡死在一个非零元素上，条件 `nums[i] == 0 and nums[j] != 0` 再也无法满足。
- 引导：`i` 的正确语义是"下一个非零元素的放置位"，应在 `nums[j] != 0` 时交换并前进 `i`——条件应只依赖 `j` 的扫描结果。

**Edge case check**：
- 应补充用例：`[1, 0, 2]`（开头非零、中间夹 0）、`[1, 2, 3]`（全非零）、`[0, 0, 0]`（全零）、单元素数组。
- 任务 1/2 的单元素与 `k=0` 边界已验证正确。

**Code quality tips**：
- 测试脚本在 Windows GBK 终端会因 `✓`（✓）崩溃：`python starter.py` 直接抛 `UnicodeEncodeError`。改用 ASCII 标记（如 `[OK]`）或运行 `PYTHONIOENCODING=utf-8 python starter.py`。

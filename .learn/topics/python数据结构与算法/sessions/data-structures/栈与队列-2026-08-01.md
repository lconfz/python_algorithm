## Positioning

数组的"受限使用"：栈和队列是只允许在有限位置操作的线性结构。栈是递归、DFS、表达式求值的底层；队列是 BFS、任务调度的底层。紧接数组学习，理解"限制反而带来清晰"。

## Core Mechanism

**栈（Stack）——后进先出 LIFO**，三条精确规则：

1. 所有操作都在栈顶：push（入栈）、pop（出栈）、peek（看栈顶）都是 O(1)。
2. Python 没有内置 Stack 类，用 list 模拟：`append` = push，`pop()` = pop，`stack[-1]` = peek——**栈顶在 list 的末尾**（均摊 O(1) 那一端）。
3. 因为后进先出，"最近的未处理项"永远在栈顶——这是它解决括号匹配、函数调用、撤销功能的关键。

**队列（Queue）——先进先出 FIFO**，三条精确规则：

1. 入队（enqueue）在队尾，出队（dequeue）在队头，正确实现下都是 O(1)。
2. **用 list 模拟队列是错误的**：`list.pop(0)` 是 O(n)（元素整体前移）。必须用 `collections.deque`：`append` 入队、`popleft` 出队。
3. deque 是"块链表"：一段段连续内存（块）用指针连接，两端操作 O(1)；代价是**随机访问 O(n)**（要跨块移动），所以 deque 没有 O(1) 索引。

**栈与递归的关系**：函数调用本身就是栈——每次调用压入"调用帧"，返回时弹出。递归 = 系统帮你管理栈；手写栈 = 显式模拟递归（消除递归）。所以 DFS 天然用栈（或递归），BFS 天然用队列。

## Analogy

- **栈：一摞盘子**——只能从顶部拿、往顶部放；要拿最下面的盘子得先拿掉上面所有（LIFO）。类比不覆盖：真实的一摞盘子不能随便"看中间"，但 Python list 底层仍是数组，语言层面允许 `stack[5]` 随机访问——栈的"受限"是约定而非强制。
- **队列：食堂打饭**——先来先服务，新同学排到队尾，队头打完就走（FIFO）。类比不覆盖：deque 是双端队列，两头都能进出（"排队中途可以插队/离开"），严格 FIFO 队列只是 deque 的一种用法。

## Code Example

```python
from collections import deque

# 1. 栈：括号匹配（栈的经典应用）
def is_balanced(s: str) -> bool:
    stack = []                          # list 当栈
    pairs = {')': '(', ']': '[', '}': '{'}
    for ch in s:
        if ch in '([{':
            stack.append(ch)            # push O(1)
        elif ch in ')]}':
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()                 # pop O(1)
    return not stack                    # 栈空 = 全部配对

print(is_balanced("([{}])"))   # True
print(is_balanced("([)]"))     # False —— 最近匹配原则

# 2. 队列：deque 实现（list 当队列是 O(n) 陷阱）
q = deque()
q.append("任务1")               # 入队 O(1)
q.append("任务2")
print(q.popleft())             # 出队 O(1) → 任务1（先来先服务）
print(q[0])                    # peek 队头

# 3. 对比：list 当队列为什么慢
lst_q = []
lst_q.append(1); lst_q.append(2)
# lst_q.pop(0)   # O(n)！剩余元素整体前移 —— 大流量下卡死

# 4. deque 的代价：随机访问 O(n)
dq = deque(range(10))
# dq[5] 需要从块链表跨块找，O(n)；list 的 d[5] 是 O(1)
```

**Walkthrough**：

- **括号匹配**是栈最优雅的应用：遇到左括号 push，遇到右括号时"最近的一个左括号"（栈顶）必须与它配对——"最近匹配"正是 LIFO 语义。`([)]` 失败的瞬间是右括号 `)` 遇到栈顶 `[`，配对失败。`[()]` 这类嵌套没问题，因为栈顶永远是"最新的"。
- **deque 队列**：popleft 从队头取，append 从队尾加，都 O(1)。list 的 pop(0) 要把后面所有元素往前挪一位——这直接复用数组第一讲的复杂度知识。
- **deque 不是万能**：它是"双端链表 + 块"结构，索引 `dq[1000000]` 要跨块移动 O(n)；要随机访问就该用 list。

## Common Misconceptions

1. **以为 Python 有内置 Stack/Queue 类** —— 没有。栈用 list 模拟（append/pop），队列用 collections.deque。
2. **用 list 当队列** —— `pop(0)` O(n)。频繁出队的场景必须 deque。
3. **以为 deque 什么都快** —— 两端 O(1) 但随机访问 O(n)。"双端队列"不是"数组的替代品"。
4. **以为栈顶在索引 0** —— Python list 模拟栈时栈顶是**末尾**（append/pop 都是 O(1) 那端）。在头部 push/pop 反而是 O(n)。
5. **把递归和栈割裂** —— 递归用的就是系统调用栈；"递归改循环"的本质是"自己管理栈"。递归深度超限（RecursionError）就是系统栈溢出。

## Socratic Check

1. `"([)]"` 用上面的 is_balanced 会返回什么？在哪个字符处开始失败？
   > **答案**：False。处理到第 3 个字符 `)` 时，栈顶是 `[`，而 `)` 期望配 `(`，不匹配直接返回 False。这就是"最近匹配"的体现。
2. 如果要用栈模拟"浏览器后退按钮"，push 和 pop 分别对应什么操作？
   > **答案**：每次访问新页面 push（入栈）；点后退 pop（回到上一页并弹出）。栈顶永远是"最近访问的页面"——LIFO 完美匹配"后退"语义。

## Quick Summary
- 栈 LIFO：list 模拟（append/pop 都是 O(1)，栈顶在末尾）；应用：括号匹配、函数调用、撤销/后退
- 队列 FIFO：必须 deque（list.pop(0) 是 O(n) 陷阱）；应用：任务调度、BFS
- deque 是块链表：两端 O(1)、随机访问 O(n)
- 递归的本质是系统调用栈；DFS 用栈/递归，BFS 用队列

## Positioning

数据结构领域的起点——最基础、最常用的线性结构。栈、队列、双指针、滑动窗口等几乎所有后续概念都建立在它之上。

## Core Mechanism

**数组（Array）** 是计算机科学中最基础的数据结构：把元素连续存放在一块连续内存中，通过索引（偏移量 offset）直接计算元素地址，因此随机访问是 O(1)。

**Python 的 `list` 本质是动态数组（dynamic array）**，有三条精确规则：

1. **底层是一块连续内存数组，但存的是对象引用（指针）**，而不是元素本身。所以一个列表里可以放不同类型的对象（整数、字符串、任意对象），代价是每个元素多一个指针的内存开销。这是 Python list 与 C/Java 数组的本质区别——C 数组存元素本身，要求同类型。
2. **自动扩容**：当空间不足时，CPython 申请一块更大的内存（按比例过度分配），把旧元素全部搬过去，再释放旧内存。因为扩容发生的频率呈几何级数递减，`append` 的**均摊复杂度是 O(1)**（平均每次追加的开销是常数，尽管偶尔一次扩容是 O(n)）。
3. **索引从 0 开始**。连续内存意味着：在头部或中间插入/删除元素，必须把后面所有元素整体"挪动"一位，所以是 O(n)。

完整复杂度规则：

| 操作 | 复杂度 | 原因 |
|---|---|---|
| 索引访问 `arr[i]` | O(1) | 直接计算地址 |
| 末尾追加 `append` | O(1) 均摊 | 偶尔扩容摊平 |
| 末尾弹出 `pop()` | O(1) | 缩短一位 |
| 头部插入/删除 `insert(0,x)` `pop(0)` | O(n) | 所有元素后移 |
| 中间插入/删除 | O(n) | 后半段后移 |
| 查找 `x in arr` | O(n) | 顺序扫描 |
| 切片 `arr[a:b]` | O(b-a) | 复制出新列表 |

## Analogy

**一排带编号的储物柜**：

- 知道柜子编号，直接走过去开柜子 → 随机访问 O(1)
- 想在 3 号柜和 4 号柜之间塞一个新柜子，必须把 4 号以后的柜子全部往后挪 → 插入 O(n)
- 柜子不够用了，要租更大的房间、把所有柜子搬过去 → 动态扩容

**这个类比不覆盖的地方**：储物柜每格容量固定，放不下"任意大小"的物品；而 Python list 存的是"标签/卡片"（引用），卡片可以指向任何对象，所以能异构。另外储物柜不会自己扩容，Python list 会在内部自动完成。

## Code Example

```python
import sys

# 1. 基本操作与对应复杂度
arr = [1, 2, 3]
arr.append(4)          # 末尾追加 —— 均摊 O(1)
print(arr[0])          # 随机访问 —— O(1)
arr.insert(0, 0)       # 头部插入 —— O(n)，后面所有元素要挪一位
print(arr)             # [0, 1, 2, 3, 4]

# 2. 观察动态扩容：内存跳跃式增长（容量按比例翻，不是每次 +1）
lst = []
prev = 0
for i in range(40):
    lst.append(i)
    size = sys.getsizeof(lst)
    if size != prev:
        print(f"len={len(lst):2d} 内存={size:3d} 字节")
        prev = size

# 3. 引用 vs 拷贝：赋值是别名
a = [1, 2, 3]
b = a                # b 只是 a 的别名，指向同一个列表对象！
b.append(4)
print(a)             # [1, 2, 3, 4] —— a 也变了

c = a[:]             # 切片产生浅拷贝：新列表，元素引用不变
c.append(5)
print(a)             # [1, 2, 3, 4] —— 不受影响

# 4. 嵌套列表的经典坑：* 乘法复制的是引用
grid = [[0]] * 3
grid[0][0] = 9
print(grid)          # [[9], [9], [9]] —— 三个位置指向同一个内层列表！
```

**Walkthrough**：

- 第 1 段演示三个核心操作。`insert(0, 0)` 之所以是 O(n)，是因为元素 1,2,3,4 都要后移一位给新元素腾位置。
- 第 2 段用 `sys.getsizeof` 观察列表对象占用的内存字节数：注意输出中的"内存"值**跳跃式**增长（例如从 56 → 88 → 120 → 184…），而不是每 append 一次 +8 字节——这就是扩容瞬间。扩容一旦发生，旧内存里的所有指针都要搬到新内存，成本 O(n)，但下一批 n 次 append 都不用扩容，摊平后每次均摊 O(1)。
- 第 3 段演示引用语义：`b = a` 不复制，只是给同一个对象多起了一个名字；`a[:]` 才产生新列表（浅拷贝）。
- 第 4 段是嵌套列表最经典的坑：`[[0]] * 3` 把**同一个**内层列表的引用复制了三次，修改任意一个"格子"会同时反映在三个位置。

## Common Misconceptions

1. **`b = a` 以为复制了列表** —— 实际上 b 和 a 指向同一个对象，改 b 等于改 a。复制用 `a[:]`、`list(a)` 或 `copy.copy(a)`（浅拷贝），完全独立的副本用 `copy.deepcopy(a)`（深拷贝，递归复制嵌套结构）。
2. **`[[0]] * 3` 以为创建了 3 个独立子列表** —— 实际是 3 个共享引用。正确写法是列表推导 `[[0] for _ in range(3)]`。
3. **以为 `x in list` 是 O(1)** —— list 只能顺序扫描，O(n)；需要常数时间查找请用 `set` / `dict`。
4. **混淆 `append` 与 `extend`** —— `a.append([4, 5])` 把整个列表当一个元素塞入（变成嵌套），`a.extend([4, 5])` 把元素展开逐个追加。
5. **切片是"复制"不是"视图"** —— `a[1:3]` 得到新列表，改它不影响原列表（这与 numpy 数组的切片不同，numpy 切片是共享内存的视图）。
6. **遍历时删除元素会跳项** —— `for x in a: a.remove(x)` 不会清空列表，因为删除导致元素前移、索引跳过。正确做法是倒序遍历或先筛选再重建。

## Socratic Check

1. `a = [1, 2, 3]`，然后执行 `b = a; b.append(4)`，此时 `print(a)` 输出什么？为什么？
   > **答案**：`[1, 2, 3, 4]`。`b = a` 是别名赋值，两者指向同一个列表对象，`b.append(4)` 修改的是那个共享对象，a 自然能看到。
2. 为什么 `pop(0)`（删除头部）比 `pop()`（删除尾部）慢得多？如果程序需要频繁从头部取数据，应该用什么结构？
   > **答案**：`pop(0)` 必须把剩余所有元素前移一位，O(n)；`pop()` 只缩短列表，O(1)。频繁从两端操作请用 `collections.deque`（双端队列），它的两端操作都是 O(1)。

## Quick Summary
- Python list 是**动态数组**：底层连续内存存对象引用，随机访问 O(1)，可自动扩容
- `append`/`pop()` 均摊 O(1)；头部与中间插入/删除 O(n)；`in` 查找 O(n)
- 赋值是**别名**不是拷贝；`*` 复制嵌套列表会**共享内层引用**
- 频繁两端操作改用 `deque`，频繁查找改用 `set`/`dict`
